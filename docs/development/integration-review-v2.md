## Result and corrected finding

No definite unresolved P1 source defect was identified in the reviewed scope. One recoverability defect was found during independent review and corrected by the save-store author before this document was written:

**Full-directory archival could lock itself out after its first failed move.** With exactly 1,024 active root entries and no archive directory, creating `archive` added a 1,025th entry. If the first rename failed, the old scanner rejected every later archive attempt. The revised scanner gives only the fixed, verified archive control directory a separate allowance; active entries remain bounded at 1,024 and total root entries at 1,025. Exact spelling, non-link status and directory status are checked before the exemption (`game/runtime/save_store.gd:205-250`). Hidden, temporary and unrelated entries still consume active capacity. This correction was re-read and paper-traced; fault-injection verification remains NOT_RUN.

## Paper traces, not executions

1. **Repeat route choice without losing facts.** COLLECT reaches PLAN with the parcel fact. WAIT reaches REST; observing a path adds its fact. RETRY returns PLAN and erases WAIT/RETRY from the route witness, while both facts remain. TAKE_ROUTE is then eligible. A self-loop that grants a fact similarly keeps its grant despite an empty added route segment.
2. **Corrupt history hidden inside a loop.** An imported history containing an action from the wrong node, a missing grant or a step after terminal returns an error in the original replay loop. The later erasure helper never receives that rejected history; the existing live session remains.
3. **Full root and failed first archive move.** Exactly 1,024 active entries plus newly created, verified `archive` remains within the revised scanner bounds. A failed rename moves no file; after the underlying I/O cause is corrected, another explicit archive call can scan again. Ordinary save still refuses until active capacity is actually freed.
4. **Corrupt high generation and partial archive.** A corrupt highest filename stays active, two newest intact files stay active, and only older intact records are eligible. After one rename and a second failure, the first appears in `moved`, others remain, and the next write still selects a generation above the corrupt highest filename.
5. **Old button after chapter switch.** A free-mode option carries revision R. A successful application chapter entry first saves free, switches the session and increments the revision. The old callback is rejected as `STALE_PRESENTATION`; returning to free also changes revision. Rebinding the panel to a different application additionally invalidates the old binding epoch.
6. **Explicit archive with incompatible content.** Store envelope/hash validation can succeed while the coordinator rejects the mode, schema or quest fingerprint. The staged restore is not published, the current state and revision remain, and no new save is written by the load call.

## Remaining boundaries

- A compact route is a **current-node path witness**, not a full choice/observation audit log. Final monotonic facts cannot establish when or where a fact was acquired, and SHA-256 is not authentication. Restoring a save must not replay rewards or derive economic transactions from this route.
- The application restricts externally reported facts, but does not authenticate a player or network event. Actor ownership, interaction range/collision configuration and scene integration remain the scene owner's responsibility. No main scene is provided or claimed playable.
- Every successful observation currently advances presentation revision, including an already-observed fact. Repeated observations can invalidate visible options; callers should refresh from `present()` and must not fabricate a success response for a stale command. This is a conservative invalidation choice, not a reward or transition.
- Save-before-switch does not make all gameplay choices autosaved. Abrupt termination between explicit saves can still lose unsaved progress. A chapter record contains only chapter state; it is not a complete suspended-world checkpoint. Cross-mode clocks, inventory, rewards and world snapshots remain outside this milestone.
- Archive operations are explicit and bounded. Corrupt or unknown files can still fill active capacity; archive capacity can fill; no automatic deletion, archive rotation or indefinite-storage guarantee exists. Retention counts envelope-valid files, while quest/content compatibility is checked only at load time.
- The store remains synchronous, single-main-thread/single-process. No cross-process lock, atomic destination reservation, power-loss guarantee, Windows antivirus/reparse-point behavior or target-device performance has been demonstrated.
- The source checks do not prove that Godot imports these scripts or that the controls, physics overlap, focus, saving or recovery work on Windows. The next authorized execution must collect those separate observations instead of marking this review as a test pass.
