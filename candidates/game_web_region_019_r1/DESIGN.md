## 独有设计决策
- **记录主张与模拟观察分开**：即使底层 `snapshot()` 始终计算 `actual_reachable` 和 `actual_visible`，019 的证据卡只在 `inspected=true` 时显示它们是“本地模拟检查结果”。这是为避免把未点击核对的内部衍生值错当玩家已调查证据。
- **固定快照不存个人信息或外部数据**：纯合成文本、单份 `String`，重置/换场清掉。此方案牺牲长期可追溯性，换来不批准新的存档/外部接口。
- **建议不自动执行**：下一步提示只展示文字，绝不调用模型的 `move_player/correct_record/undo_last`。使用者仍通过原有显式按钮完成修改。
- **不触碰采样视线/四向路由算法**：019 是表达层候选，沿用 PR26 的近似性限制，不能以文字导览掩盖路线误判。
- **不修改公用控件或 InputMap**：全部功能只装入本目录，在 UI 面板里增加两只只读文本框与固定/清除按钮。宽屏和大字显示是否溢出必须后续实测；不能宣称满足 WCAG。
- **必需依赖缺失不是“降级成功”**：只有可选合成 JSON 能被原模型无害回退；缺 `state_guide.gd` 之类的脚本属于导入阻塞。

## A/B/C 预期差异（仅候选）
- A：记录声称可达且可见；已核对后可能看到“可达但被墙遮挡”而提示更正。
- B：记录初称不可达；已核对后若能绕行则提示更正“可达”。
- C：目标被隔离；提示不能穿墙，可用返回 S 的路线，并在显式核对后处理错误主张。
- **位置变化会让已核对信息失效**（来自 PR #26 模型），019 观察栏随之退回“未核对”，不能沿用旧位置的视线结论。
