## 设计目标和非目标

**目标候选：** 在获得授权之后，以**完全合成 A/B/C** 建立一个唯一的隔离验证入口，使来源/错误诊断、局部操作/撤销、文本/焦点与可选证据卡可以分别被验证，不改变任何原 PR 的事实来源。**非目标：** 把四份 Draft 直接合并；改变游戏真实地图/角色/主线；补正史；对接共享事件与存档；声称真实导航或无障碍合规；推送 main。

## 兼容路径的两种选择（都未实现）

**方案 A｜推荐：以 #28 校验结果作为未来合成加载入口，接 #26 模型，#27 只读展示可插拔。** 优点是结构错误与运行状态在不同层，减少双重 fallback；成本是需要新的显式适配合同，不能直接把 `SOURCE_ACCEPTED` 当成 #26 的 `_valid_catalog` 布尔返回。推荐的**逻辑顺序，仅为设计**：合成 JSON → 验证/记录来源 → 把已确认的合成字段传给独立局部模型 → 由模型提供 snapshot → 只读导览显示。不得将三态错误结果原样塞给 `region_model.select_scene`。

**方案 B｜保守：四个 PR 继续作为独立技术样本，只做文档与截图式对照。** 不生产任何“集成引擎”，避免在项目资源/授权未确定时制造重叠实现。若 M1 没有得到合法 UI/存档/导航范围批准，就优先方案 B。

**为什么推荐 A 但默认执行 B：** A 有机会去除多份 fallback 的语义漂移，但现在每个 PR 都没有实际导入/操作证据；在明文禁止本轮运行且不得改共享接口的条件下，自动实现 A 反而越权。因此本 N21 只记录迁移计划，不向任何原 PR 提交补丁。

## 失败、降级与可恢复性（未来建议）

- **原合成源文件缺失/坏 JSON：** 标“SOURCE_REJECTED”，显示具体字段原因；只在未来已授权的隔离候选中用**经过自检的内置 A/B/C**作 `FALLBACK_SYNTHETIC`；不回写原文件。
- **内置 A/B/C 也无法验证：** 标 `BLOCKED` 并禁止进入场景。不能冒充“显示可玩地图”。
- **选择 A/B/C、撤销、切换：** 本地记录/可观察状态只影响隔离候选，旧观察需重新核对，跨场景快照清理。
- **失焦与键盘问题：** 未来保留本地按钮级恢复，不靠强制把键盘焦点交给网格；窗口返焦没有权限自动更正、读档或移动。
- **无法迁移真实项目：** 退回四份独立候选，不重写、不合并任何现有 PR；作者可在新的任务里明确选择删减范围。
