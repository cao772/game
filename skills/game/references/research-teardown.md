# 来源研究与游戏机制拆解

## 资料筛选

优先原作者仓库、开发者演讲、官方文档、研究原文和可核查实例。记录 URL、日期、所读范围、许可和适用边界。GitHub 星标与下载量只证明关注度，不能证明效果；没有独立评价时直接说明。

Skill 的选用要读正文与关联资料，检查过时工具、固定模型、强制问答、隐藏上传、执行脚本、许可缺失和私密路径。固定 commit 与文件哈希，升级时看变化而不是自动拉最新执行。

## RE／逆向的两种含义

本项目默认做设计逆向：从合法可见的玩法、规则、开发者讲述和公开源码解释机制。若确实需要二进制逆向，先界定目标与权限，再选择工具；不因这份 Skill 自动下载、运行或分析商业游戏程序。

设计拆解顺序：
1. 选一个具体问题，例如线索怎样推动下一次探索；不要一次拆整款游戏。
2. 记录可观察片段、规则和来源，区分亲自观察、官方描述、他人分析。
3. 画出玩家信息、行动、反馈、奖励、失败与循环；找核心张力。
4. 解释可能的设计作用，列替代解释和代价。推断不得冒充开发者本意。
5. 去掉原作人物、台词、专有设定和事件顺序，提炼可迁移功能。
6. 为本项目写原创变体及一个可以检验它的设计问题，明确不同之处。

## 案例卡

记录：来源与实际阅读范围；观察到什么；机制推断；适用条件；代价；本项目原创转译；不复制的内容；待验证问题。仅看到演讲简介时不得宣称看过完整视频。

机制拆解可以从“好奇心驱动探索”“分支汇合但保留后果”“环境承载证据”“重复空间的时间变化”等具体问题入手。故事借鉴同样提炼冲突结构、悬念分配和回收方式，不照搬独特剧情链。

## 非 Skill 参考入口

- [MDA 原论文](https://users.cs.northwestern.edu/~hunicke/MDA.pdf)：规则、动态行为与体验之间的分析语言。作为设计假设工具，不当评分标准。
- [ink 官方入口](https://www.inklestudios.com/ink/)：交互叙事语言、写作手册、示例及编辑器。用于研究分支内容组织；本次不迁移引擎或引入运行时依赖。
- [Outer Wilds 开发者演讲页](https://www.gdcvault.com/play/1027368/Independent-Games-Summit-Sparking-Curiosity)：好奇心驱动探索。当前依据公开简介；未观看完整演讲。
- [Game Accessibility Guidelines](https://gameaccessibilityguidelines.com/basic/)：文本阅读、字幕、输入和感知信息的设计参考，按目标玩家与机制选择。
- [Ghidra 官方仓库](https://github.com/NationalSecurityAgency/ghidra)：软件逆向工具，作为将来已授权源码／二进制研究的工具入口；未安装，未运行，不是游戏设计 Skill。
